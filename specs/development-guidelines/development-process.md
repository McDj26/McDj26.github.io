# 开发流程

## 分支策略

### 主分支
- **main**: 主分支，包含稳定的生产代码
- **develop**: 开发分支，集成所有功能开发

### 特性分支
- **feature/**: 功能开发分支，从 develop 分支创建
- **bugfix/**:  bug 修复分支，从 main 分支创建
- **hotfix/**: 紧急修复分支，从 main 分支创建

## 开发流程

### 1. 需求分析
- 理解需求，确定功能范围
- 制定开发计划和时间线
- 评估技术可行性

### 2. 分支创建
- 从 develop 分支创建特性分支
- 分支命名格式：`feature/功能名称`

### 3. 代码开发
- 遵循代码风格指南
- 编写单元测试
- 确保代码质量

### 4. 代码提交
- 提交前运行测试
- 提交信息遵循规范格式
- 每次提交只包含一个功能或修复

### 5. 代码审查
- 创建 Pull Request 到 develop 分支
- 团队成员进行代码审查
- 解决审查中提出的问题

### 6. 测试
- 运行单元测试
- 进行集成测试
- 进行端到端测试

### 7. 合并分支
- 测试通过后合并到 develop 分支
- 删除已完成的特性分支

### 8. 发布流程
- 从 develop 分支创建发布分支
- 进行发布前测试
- 合并到 main 分支
- 打版本标签
- 部署到生产环境

## 提交信息规范

### 格式

```
<type>(<scope>): <subject>

<body>

<footer>
```

### 类型
- **feat**: 新功能
- **fix**: 修复 bug
- **docs**: 文档更新
- **style**: 代码风格修改
- **refactor**: 代码重构
- **test**: 测试相关
- **chore**: 构建或依赖更新

### 示例

```
feat(home): 添加首页轮播图功能

添加了响应式轮播图组件，支持自动播放和手动控制

Closes #123
```

## 代码审查指南

### 审查要点
- 代码质量和可读性
- 功能实现是否符合需求
- 潜在的性能问题
- 安全性问题
- 测试覆盖情况

### 审查流程
1. 检查代码是否符合代码风格指南
2. 理解代码逻辑和实现方式
3. 提出改进建议
4. 确认测试覆盖情况
5. 批准或请求修改

## 常见问题处理

### 冲突解决
- 合并前先拉取最新代码
- 解决冲突时保持代码逻辑一致性
- 冲突解决后运行测试

### 回滚操作
- 当发现严重问题时，使用 git revert 回滚提交
- 记录回滚原因和解决方案
- 重新进行测试和部署

### 性能优化
- 识别性能瓶颈
- 进行代码优化
- 监控优化效果

## 工具使用

### 开发工具
- **IDE**: Visual Studio Code
- **插件**: Volar, ESLint, Prettier
- **版本控制**: Git

### 构建工具
- **构建**: `pnpm run build`
- **开发服务器**: `pnpm run dev`
- **预览**: `pnpm run preview`

### 代码质量工具
- **ESLint**: 代码风格检查
- **Prettier**: 代码格式化
- **TypeScript**: 类型检查
